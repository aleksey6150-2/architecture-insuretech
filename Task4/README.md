# Task4. Проектирование продажи ОСАГО

## Цель

Спроектировать архитектуру запуска нового продукта — оформления ОСАГО онлайн.

Пользователь создаёт заявку с данными автомобиля. После этого система отправляет заявку во все доступные страховые компании и показывает предложения пользователю сразу по мере их поступления.

Максимальное время ожидания ответа от страховой компании — 60 секунд.

В пиковой нагрузке ожидается до 2,5 тыс. одновременных пользователей, создающих заявки на ОСАГО.

## Основные архитектурные решения

Для интеграции со страховыми компаниями выделяется отдельный сервис:

- `osago-aggregator`.

Он отвечает за:

- получение заявок на ОСАГО из внутреннего потока событий;
- отправку заявок во все доступные страховые компании;
- опрос решений по заявкам;
- публикацию каждого полученного предложения;
- фиксацию timeout, если страховая не ответила за 60 секунд.

Остальная функциональность, связанная с оформлением ОСАГО, остаётся в `core-app`.

## Хранилище osago-aggregator

Сервису `osago-aggregator` требуется собственное хранилище данных.

В нём хранятся:

- `applicationId` заявки в InsureTech;
- идентификаторы заявок во внешних страховых компаниях;
- статусы запросов по каждой страховой;
- полученные предложения;
- deadline обработки;
- количество retry;
- idempotency keys.

Хранилище необходимо, потому что сервис запускается в нескольких экземплярах и должен переживать рестарт pod без потери состояния обработки заявок.

## Интеграция core-app и osago-aggregator

Для взаимодействия `core-app` и `osago-aggregator` используется Event Streaming через Kafka.

### Topic: osago-applications

Producer:

- `core-app`.

Consumer:

- `osago-aggregator`.

Событие:

- `OsagoApplicationCreated`.

### Topic: osago-offers

Producer:

- `osago-aggregator`.

Consumer:

- `core-app`.

События:

- `OsagoOfferReceived`;
- `OsagoOfferTimeout`;
- `OsagoOfferFailed`.

Такой подход выбран, потому что получение предложений от страховых компаний является асинхронным процессом и может занимать до 60 секунд.

## Transactional Outbox

В `core-app` используется Transactional Outbox.

При создании заявки на ОСАГО `core-app` в одной транзакции:

1. сохраняет заявку в свою БД;
2. сохраняет событие `OsagoApplicationCreated` в outbox-таблицу.

Затем outbox publisher публикует событие в Kafka.

Это защищает систему от ситуации, когда заявка создана, но событие для `osago-aggregator` не опубликовано.
